# A Workflow for GenAI-Assisted Research

Capture → Organize → Distill → Express

---

## The CODE Framework

Tiago Forte's method for compounding research instead of resetting it each time

- **Capture** — collect raw material as you find it
- **Organize** — sort it against your actual output
- **Distill** — extract the essence into your own words
- **Express** — turn distilled notes into a finished deliverable

> Read more: [Building a Second Brain — overview](https://fortelabs.com/blog/basboverview/)

---

## Why a workflow?

- Unstructured prompting
	- generic, ungrounded, unverifiable answers
- Paired with "spec, then plan, then execute"
	- how coding agents work best
- CODE is a process you apply to notes, not a set of folders

---

## Filing system vs. workflow

- Two folders: **`Notes/`** — your active work — and **`Resources/`** — reference material
- Adapted from Tiago Forte's **PARA**, simplified for one session
- **PARA** organizes *where* notes live; **CODE** describes *what you do* to them — the two aren't the same thing

---

## Question → Claim → Evidence

*For academic-style questions — not just "which option wins"*

- **Question**
	- the precise thing you're investigating
- **Claim**
	- your provisional thesis, revised as sources come in
- **Evidence**
	- citations and data that support or challenge the claim
- Link claim ↔ evidence

---

## 1. Capture

- Feed primary sources directly to the model
	- grounded, cited capture
- Ask for structured extraction: *"extract X into a table with columns Y, Z"*
- Keep it raw and ungroomed at this stage — always cited

---

## 2. Organize

- Plan before you build — spec first, execute second
- Sort captured material against your report structure
- Still the same notes — just grouped by where they'll be used

---

## 3. Distill

- Take the raw sources and synthesize them into linked, atomic notes
- One idea per note; links do the work that copy-pasting used to do
- The output is the note itself, rewritten in your own words

---

## 4. Express

- Draft `report.md` straight from your distilled notes — you're assembling, not composing from scratch
- Prototype: turn the same distilled data into an interactive dashboard

---

## Human in the loop

- Agents can hallucinate, misread a source, or drift off-brief
- Review at each handoff: source → extraction → note → draft
- Trust, but verify — every claim traces back to its source

---

## Planning & approving

- Agents propose a plan before touching files — review it, then approve
- Claude Code's **Plan Mode**, Codex's plan step
- Risky actions (delete, `git push`) prompt for approval by default

---

## Andrej Karpathy's "LLM Wiki"

- Published April 2026 — an agent maintains a structured wiki instead of re-deriving answers from raw docs each time
- New source in → agent updates existing pages, flags contradictions
- Knowledge compounds instead of resetting on every query

> Read the gist: [gist.github.com/karpathy/llm-wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)

---

## Applying it today

- Drop sources into `Notes/` as you find them
- Ask your agent to maintain your distilled notes as a wiki
- Browse the result in Obsidian — graph view shows how ideas connect

# GenAI Tools

Coding agents that read, write, run, and iterate — not just chat

--

## Two layers of tools

- **Agentic coding CLIs** — build the report and dashboard prototype
  - Claude Code, Codex, OpenCode, Antigravity
- **Model access layer** — choose and compare which model powers them
  - OpenRouter

---

## Prompt Engineering Basics

- Be clear and direct — say exactly what you want, like briefing a new colleague
- Add context — explain *why*, not just *what*, so the model can generalize
- Use examples — 2–3 concrete examples steer output better than a long description
- Give it a role — a one-line role up front focuses tone and behavior

---

## What's a harness?

- A **harness** wraps a model with tools (file read/write, shell, git, browser) and a loop: plan → act → observe → repeat
- The model alone can't touch your files — the harness is what lets it read, edit, run, and iterate
- Same underlying model, different harness → different capabilities and workflow

---

## Claude Code

- Anthropic's agentic coding CLI, runs in your terminal
- Reads and writes files, runs code and tests, uses git — plans before it executes
- Used to build this workshop's `Resources/solution/`

---

## Codex

- OpenAI's agentic coding system: terminal CLI, IDE extension, cloud via ChatGPT
- Runs GPT-5-class "Codex" models tuned for coding
- Same core loop as Claude Code: plan, edit, run, fix

---

## OpenCode

- Open-source, terminal-based coding agent (`sst/opencode`)
- Provider-agnostic: bring your own model — Claude, GPT, Gemini, or local
- One agent UI across many providers

---

## Antigravity

- Google's agent-first development platform — desktop app + CLI
- Editor view plus a "manager" view to run several agents in parallel
- Multi-model out of the box: Gemini 3, Claude, GPT-OSS

---

## Skills: Claude Code & Codex

- A skill is a folder: `SKILL.md` (required) + optional `scripts/`, `references/`, `assets/`
- Progressive disclosure: short description always loaded → full instructions loaded when relevant → linked files loaded on demand
- Claude Code: `.claude/skills/`; Codex: `~/.codex/skills/` — both matched by description
- Unlike `CLAUDE.md` / `AGENTS.md`, skills stay out of context until needed

---

## OpenRouter

- One API / marketplace in front of dozens of model providers
- Compare cost, speed, and quality per task
- Point any tool above at it to swap models without changing your workflow

---

## At a glance

| Tool        | Interface               | Models                     | Best for                         |
| ----------- | ------------------------ | --------------------------- | --------------------------------- |
| Claude Code | Terminal                | Claude                     | Deep, file-aware agentic coding  |
| Codex       | Terminal / IDE / cloud  | GPT-5-Codex                 | Same, OpenAI ecosystem           |
| OpenCode    | Terminal                | Any (via provider)         | Provider-agnostic, one UI        |
| Antigravity | Desktop IDE             | Gemini 3, Claude, GPT-OSS   | Multi-agent orchestration        |
| OpenRouter  | API                     | 100+ models                 | Model access & comparison layer  |
